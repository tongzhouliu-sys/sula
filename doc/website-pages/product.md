# 把数字能力，真正纳入企业组织

数僚 SULIA 不是另一个对话入口，而是一套数字员工全生命周期管理系统。从“入职”到“在岗”，从能力授权到协同交付，再到成果审查与资产沉淀，企业第一次能够用统一方式管理不断增长的数字劳动力。

## 数字员工全生命周期管理

**入职与岗位配置** → **能力与工具授权** → **协同工作** → **成果审查与资产化** → **持续评估与成长**

### 01｜入职与岗位配置

先定义“谁”，再决定“能做什么”。

企业可为数字员工建立完整岗位档案，包括姓名、头像、员工编号、部门、岗位、职责、服务对象、业务负责人、风险等级与在岗状态。每一位数字员工都以明确的组织身份进入团队，不再是难以区分的通用工具。

- 使用岗位模板快速创建专业角色
- 配置职责范围、服务说明与交付标准
- 指定业务负责人、使用部门与服务人群
- 管理待审核、已发布、暂停、失联与归档状态

### 02｜能力与工具授权

让数字员工获得完成岗位工作的必要能力，同时守住数据与操作边界。

管理员可以通过零代码看板，为数字员工分配企业知识、专业能力、业务连接和数据范围。系统以默认最小权限为原则；未明确授权的资源不可访问，高风险动作进入人工审批。

- 按岗位配置知识、能力与业务连接
- 按人员、部门、员工和资源四个层级控制访问
- 区分读取、编辑、外发、审批等操作等级
- 设置敏感数据策略、使用时段与成本边界
- 对高风险动作启用二次确认和人工接管

### 03｜协同工作

人发起目标，数字员工协同执行，人掌握关键决定。

用户可以选择合适的数字员工，提交任务、资料和交付要求。复杂任务由不同岗位协作完成，工作台持续展示当前阶段、责任角色、引用依据、待确认事项、异常与最终成果。

- 对话、任务、附件与成果在同一工作上下文中流转
- 按研究、执行、复核、交付等岗位分工协作
- 展示用户可理解的计划、进度、状态与失败原因
- 支持停止、重试、转交、补充资料和人工接管
- 关键节点由指定人员审阅、批准或退回

### 04｜成果审查与资产化

交付不是终点，而是企业能力积累的开始。

数僚将报告、表格、方案、审核意见、回复内容与知识条目统一关联到数字员工、任务、来源和版本。经人工确认的优质成果可进入企业资产库，为后续工作提供可靠参考。

- 记录成果来源、创建时间、责任人和审阅状态
- 支持版本比较、保留期与敏感等级
- 按授权查看、预览、下载与分享
- 将优质成果沉淀为模板、知识与标准流程
- 统计成果复用、节省工时与交付质量

### 05｜持续评估与成长

以业务结果衡量数字员工，而不是只看调用次数。

管理者可持续观察任务完成率、人工介入率、平均交付时间、成果采纳率、复用率、异常类型与单位成功任务成本。岗位能力可以根据真实反馈逐步调整，形成可治理的成长闭环。

## 数字员工目录

企业所有可用数字员工集中呈现。员工卡片以业务语言说明岗位、擅长事项、适用人群、当前状态和权限范围，用户无需理解底层技术即可找到合适的数字同僚。

> **[截图占位 1：数字员工目录与岗位卡片]**
>
> **画面内容：** 页面包含部门筛选、岗位搜索、收藏与最近使用；卡片展示头像、姓名、岗位、服务简介、当前状态、可服务对象和代表性成果。
>
> **交互说明：** 用户可按部门或任务类型筛选，点击岗位卡片进入员工详情；仅展示当前用户已获授权的数字员工，暂停或异常状态必须清晰可见。
>
> **设计意图：** 用“选同事”的熟悉体验替代复杂配置，让第一次使用者也能快速理解谁适合完成什么工作。
>
> **建议规格：** 16:10 桌面端主界面；移动端改为单列岗位卡片。深宙蓝承载导航与岗位身份，智能青表示可用与协作状态，成果琥珀金只用于关键价值节点。

### 岗位卡片应回答的五个问题

| 用户问题 | 界面答案 |
|---|---|
| 这是谁？ | 姓名、头像、员工编号、部门与岗位 |
| 能帮我做什么？ | 服务说明、典型任务与示例成果 |
| 现在能否工作？ | 在线、忙碌、离线或异常状态 |
| 我可以交给它什么？ | 已授权能力、资料范围与操作边界 |
| 出现问题找谁？ | 业务负责人、人工接管与支持入口 |

## 零代码能力与权限配置

管理员从岗位出发配置能力，不需要编写复杂指令。能力、知识、业务连接、数据范围和审批规则以可视化模块组合，并在发布前给出权限摘要与风险提示。

> **[截图占位 2：零代码技能与权限配置看板]**
>
> **画面内容：** 左侧为岗位与人员范围，中部为能力、知识和业务连接模块，右侧为权限摘要、数据等级、审批策略与发布检查。
>
> **交互说明：** 管理员通过选择和开关完成配置；新增敏感权限时显示影响范围，发布前必须通过完整性检查，高风险变更进入审批。
>
> **设计意图：** 把技术配置翻译成企业管理员熟悉的“岗位—能力—资源—审批”关系，降低上手门槛，同时避免为了简单而牺牲边界。
>
> **建议规格：** 16:10 桌面端管理界面；权限变化使用差异视图呈现。深宙蓝强化企业级安全感，智能青表示已授权，成果琥珀金提示待审批或关键变更。

### 配置对象

| 配置层 | 管理内容 | 企业价值 |
|---|---|---|
| 岗位 | 职责、服务对象、交付标准 | 明确数字员工为何存在 |
| 能力 | 专业能力、任务模板、知识范围 | 确保数字员工胜任岗位 |
| 连接 | 企业系统、消息渠道与外部服务 | 让能力进入真实业务流程 |
| 权限 | 人员、部门、资源与操作等级 | 避免跨范围访问和误操作 |
| 策略 | 数据等级、审批、时段与成本 | 让使用符合企业制度 |
| 发布 | 校验、审核、启用、暂停与归档 | 让变更可控、可回退 |

## 人机协同工作台

每项任务都有连续上下文：目标、资料、沟通、计划、执行、审批、异常、交付与成果归档在同一处呈现。用户看得懂正在发生什么，也随时可以补充信息或接管。

> **[截图占位 3：人机协同工作台与任务交付记录]**
>
> **画面内容：** 左侧为当前数字员工与任务列表，中部为对话、计划、处理进度和交付内容，右侧为引用依据、审批请求、成果版本与责任记录。
>
> **交互说明：** 用户可新建任务、上传资料、查看阶段进度、处理待确认事项、停止或重试任务，并对最终成果进行采纳、退回或归档。
>
> **设计意图：** 让数字员工的工作“可见但不过度技术化”，把注意力放在目标、依据、风险和成果，而不是内部运行细节。
>
> **建议规格：** 16:10 桌面端工作台；关键信息在 1366×768 视口内无需横向滚动。深宙蓝稳定承载结构，智能青表现进度，成果琥珀金聚焦最终交付。

### 人与数字员工如何分工

| 人负责 | 数字员工负责 |
|---|---|
| 定义目标、优先级与成功标准 | 处理高频、重复、信息密集的执行工作 |
| 提供业务背景与必要资料 | 检索、整理、对比、生成初稿与跟踪进度 |
| 审阅关键依据与风险 | 主动标记冲突、缺口与待确认事项 |
| 批准高风险动作 | 在授权范围内完成标准化步骤 |
| 作出最终判断并承担责任 | 交付可检查、可追溯、可复用的成果 |

## 多员工协同架构

复杂工作往往不是一个岗位独立完成。数僚支持数字员工按职责接力：前置岗位完成资料归集，专业岗位完成分析，审核岗位检查风险，交付岗位形成统一成果。

### 一份任务，四种清晰角色

1. **任务负责人**：理解目标、组织步骤、对最终交付负责。
2. **专业执行者**：按领域完成检索、分析、撰写或处理。
3. **质量审阅者**：检查依据、完整性、风险和品牌或制度一致性。
4. **人类决策者**：确认关键判断、批准高风险动作、决定是否采纳。

每次交接都保留任务来源、责任角色、输入输出与时间记录，避免多方协作中的信息丢失和责任模糊。

## 成果资产中心

### 从“文件堆积”到“可复用的组织记忆”

成果资产中心按员工、部门、任务、日期、类型、敏感等级和审阅状态组织内容。被授权的员工可以快速找到可信版本；管理者可以识别高价值模板与知识缺口。

- 报告、表格、图片、方案与审核意见统一管理
- 原始资料、处理任务与最终成果建立来源关系
- 版本、审阅、保留和法律留存策略可配置
- 访问与下载记录进入审计
- 优质成果可转为标准模板或知识条目

## 企业级安全与合规保障

### 数据隔离

- 按企业、部门、人员、数字员工和资源实施分级访问
- 敏感数据依据等级进入指定处理环境
- 企业凭证采用受控安全引用，不在前端或普通内容中暴露
- 文件上传、预览、下载与外发均经过策略检查
- 安全隔离算力底座支持不同信任域按需部署

### 权限审计

- 未明确授权的员工、任务、成果与业务连接默认不可访问
- 能力、数据和连接授权遵循最小必要原则
- 高风险配置和外发动作支持审批与二次确认
- 记录操作者、目标资源、策略结果、审批状态与变更差异
- 异常、越权尝试和敏感操作形成可检索审计记录

### 责任可追溯

- 任务关联发起人、数字员工、参与岗位与人工负责人
- 成果关联来源资料、处理过程、版本和审阅状态
- 失败、重试、转交、接管与最终处置均有记录
- 系统异常时支持停止、恢复、回退与人工接管
- 不展示内部敏感信息，只呈现业务所需的可解释过程

> 安全不是上线前的一次检查，而是贯穿“入职、授权、工作、交付、归档、离职”的持续治理机制。

## 极简开始，逐步扩展

### 第一步：选择一个可衡量流程

优先选择高频、规则相对清晰、资料可获得、结果可审阅的工作，例如研报初筛、技术知识问答、内容质检或合同条款比对。

### 第二步：定义一位数字员工

明确岗位职责、服务对象、输入资料、权限边界、人工审阅点与成功指标。

### 第三步：小范围试点

在真实但受控的任务中验证交付时间、完成率、人工介入率、成果采纳率与使用体验。

### 第四步：复制经过验证的岗位

把通过验证的能力、流程与治理规则扩展到更多团队和场景，持续沉淀企业资产。

## 常见问题

### 数僚会取代现有员工吗？

不会。数僚的目标是把员工从重复、耗时、信息密集的工作中释放出来。人负责目标、判断、创造、关系与最终责任；数字员工负责扩大执行能力。**数僚提升人的核心价值，绝不取代人的工作。**

### 使用数僚需要会编程吗？

普通使用者不需要。员工目录、任务工作台和成果中心都使用业务语言。管理员可通过零代码看板完成大多数岗位、能力、权限与审批配置；复杂企业集成由专业团队支持。

### 数字员工可以访问企业所有数据吗？

不可以。访问遵循按需授权与默认拒绝原则。数字员工只能使用完成岗位工作所必要、且已明确授权的数据和能力。

### 复杂或高风险任务由谁决定？

人。企业可以为特定数据、动作和业务场景设置强制审阅或审批；用户也可以随时停止、补充资料、退回或接管任务。

### 如何衡量产品价值？

建议同时观察任务完成率、平均交付时间、节省工时、成果采纳率、人工介入率、知识复用率、异常率与单位成功任务成本，并以试点前后的同口径数据进行比较。

# 我们相信，智能的下一步是成为值得信赖的同僚

技术真正进入组织，不只因为它足够聪明，更因为它拥有清晰的角色、可靠的边界、可见的责任和与人协作的温度。

数僚 SULIA 因此而生。

## 品牌故事

企业里，每一位员工都有姓名、岗位、职责、协作对象和成长轨迹。员工知道该完成什么，也知道在什么边界内工作；他们的经验会沉淀为组织能力，成果会成为企业继续向前的基础。

但当智能能力最初进入企业时，组织得到的往往只是分散的工具：一个写作入口、一个问答窗口、一段自动流程。它们能够完成许多动作，却很难真正成为团队的一部分。企业无法清晰回答谁在负责、谁能访问什么、谁完成了什么，也难以让经验随时间持续积累。

我们由此意识到，智能技术的下一步不只是“更强”，而是“更组织化”。

数僚从“员工”而不是“模型”开始。我们为每一位数字员工建立身份与岗位，为每一项能力划定权限，为每一次协作留下履历，为每一份成果建立来源、版本和归属。

当数字员工可以被组织看见、理解、调度和信任，智能才真正成为长期生产力。

> **管理数字员工，释放组织生产力。**

SULIA 延续“数僚”的音感，以简洁、友好、国际化的方式承载品牌。它不需要被包装成复杂的技术缩写；它首先是一支可管理、可协同、可成长的数字员工团队的名字。

> **数僚不是替代员工的概念，而是扩展员工能力的组织方式。**

## 品牌使命

### 让每一个组织都能安全、简单地拥有自己的数字员工团队

我们希望把先进的智能能力，从少数技术人员的工具，变成每个业务团队都能理解、使用和管理的组织能力。

### 我们坚持

| 原则 | 我们如何践行 |
|---|---|
| 人始终是主角 | 人定义目标、审阅关键依据、批准高风险动作并承担最终责任 |
| 先有岗位，再有能力 | 每位数字员工先明确职责和服务对象，再配置完成工作所需能力 |

| 成果属于企业 | 优质交付经过审阅后沉淀为可复用的组织资产 |
| 价值必须可验证 | 以任务成功、节省工时、成果采纳、员工体验和风险指标衡量 |
| 技术服务于人 | 数字员工承担重复劳动，让人专注判断、创造、关系与决策 |

## 我们想创造的工作方式

### 每位员工都有超级助攻

数字员工处理重复、耗时、信息密集的工作，为真实员工准备资料、整理依据、跟踪进度和形成初稿。

### 每位管理者都看得见数字劳动力

管理者知道有哪些数字员工、服务哪些团队、获得什么权限、完成多少任务、产生哪些成果，以及何时需要人工介入。

### 每个组织都能积累自己的智能资产

被审阅的报告、流程、模板、经验与判断依据不再散落，而是持续转化为企业自己的知识与工作方法。

### 每一次自动执行都有责任边界

高风险决定不被悄然交给系统。企业可以定义必须由谁复核、批准或接管，让速度与责任同时存在。

## 预约演示

### 为你的第一位数字员工，定义一份真正有价值的岗位

告诉我们，你的团队正在被哪些重复工作占用。我们会围绕一个真实流程，与你一起梳理岗位、能力、权限、人工审阅点与试点指标。

### 演示申请表单

| 字段 | 必填 | 表单提示 |
|---|---|---|
| 姓名 | 是 | 请输入您的姓名 |
| 公司名称 | 是 | 请输入企业或机构名称 |
| 职位 | 是 | 例如：业务负责人、信息化负责人、投资负责人 |
| 工作邮箱 | 是 | 用于发送演示安排与相关资料 |
| 手机号码 | 否 | 便于快速确认演示时间 |
| 所属行业 | 是 | 金融投资、云服务与 IT、品牌内容、政企合规或其他 |
| 企业规模 | 否 | 1–50 人、51–200 人、201–1000 人、1000 人以上 |
| 关注场景 | 是 | 可多选：知识问答、研究分析、内容运营、文档审核、流程协同、其他 |
| 当前主要痛点 | 是 | 请描述最耗时、最高频或风险最集中的工作 |
| 预计数字员工数量 | 否 | 1–3 位、4–10 位、11–50 位、50 位以上、尚未确定 |
| 部署与安全要求 | 否 | 例如：专属环境、数据隔离、审批审计、业务系统连接 |
| 希望演示时间 | 否 | 请选择日期与时段 |
| 其他说明 | 否 | 可补充试点目标、参与部门或已有基础 |

### 隐私与提交

- 勾选项：**我已阅读并同意隐私说明，授权数僚团队仅为演示沟通与方案评估处理以上信息。**
- 主按钮：**提交演示申请**
- 提交中：**正在安全提交，请稍候……**
- 提交成功：**申请已收到。数僚团队将与您联系，确认场景与演示安排。**
- 提交失败：**暂未提交成功，请检查必填信息后重试。**

### 表单设计原则

- 默认只收集安排演示所需的信息，不要求上传敏感业务资料。
- 明确标识必填与选填，错误信息出现在对应字段附近。
- 在用户同意前不将信息用于无关营销目的。
- 提交完成后展示申请编号和后续步骤。
- 企业如需签署保密协议，可在场景沟通后进入正式流程。

## 一次演示会看到什么

1. **数字员工目录**：如何按岗位找到合适的数字同僚。
2. **零代码配置**：如何定义职责、能力、数据与审批边界。
3. **协同工作台**：一项任务如何被处理、审阅和交付。
4. **成果资产中心**：如何关联来源、版本、权限与复用。
5. **安全与治理**：如何隔离数据、审计操作并保留人工接管。
6. **行业场景**：根据你的业务选择一条完整工作流演示。
7. **试点建议**：共同确定首个岗位、基线指标与验证范围。

## 常见联系问题

### 是否可以只演示一个具体行业场景？

可以。建议在表单中说明流程、角色、当前耗时和最关注的安全问题，我们将优先准备相关岗位与工作流。

### 演示前需要提供内部数据吗？

不需要。首次演示使用安全的示范数据。进入试点评估后，再根据双方确认的边界和流程处理必要资料。

### 是否支持专属环境？

可根据企业的数据隔离、网络、安全和合规要求评估专属部署方案，具体范围以正式方案为准。

### 从演示到试点通常如何推进？

通常依次完成场景访谈、流程与基线确认、岗位和权限设计、受控试点、指标复盘，再决定是否扩展。
